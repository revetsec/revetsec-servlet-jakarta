# Complete local SAML SP application host (S3)

`ServletSamlSpRecipe.java` is unpublished cookbook source compiled with Java 17. It composes the public SAML and Servlet APIs without adding an adapter/core API. Register one injected instance at the fixed `/saml/*` mapping during application startup, after supplying a trusted `Configuration`, bounded RSA signing/decryption credentials, sealing key, current `Accounts` implementation and peer admission policy to `create`. Do not register the private verification servlet or its IdP/account/clock controls.

The application owns accounts, sessions, connection registration and recovery. Use this volatile one-process recipe only where losing every pending attempt and local session on restart is acceptable. Restart also loses replay fences; drain/fence the receiver for the maximum acceptance/rollover interval before serving it again, or supply a separately qualified shared deployment design. This example does not provide a durable/shared store or certify a fleet profile.

## Trusted configuration and routes

`Configuration` contains one fixed HTTPS SP origin/entity and 1–8 distinct startup connections. Each connection pins the exact IdP entity, Redirect/POST SSO/SLO endpoints and 1–4 RSA 2048–8192 signing keys. Requests cannot supply a discovery URL, issuer, key source, algorithm policy or IdP registration. Rotation/restart is an operator deployment action. The factory uses signed AuthnRequests (`forceAuthn=true`), required signed assertions, zero skew, five-minute maximum response age, solicited-only completion and no AES-CBC opt-in. Decryption uses at most two explicitly supplied credentials. No algorithm/key/discovery retry or unsolicited fallback is added.

Routes below include the fixed mapping prefix:

| Route | Application behavior |
| --- | --- |
| `GET /saml/session` | Read status/CSRF of a current existing session; never allocate on GET. |
| `POST /saml/session` | Exact local Origin and `begin=1`, trusted peer admission and bounded explicit anonymous session allocation. |
| `POST /saml/login/{connection}/{redirect,post}` | Exact local Origin, session CSRF and current anonymous session; save sealed pending state before delivering the signed request. |
| `POST /saml/acs` | Original raw bounded form through actual `ServletSaml`; saved attempt selects the connection, then genuine signature, exact pending correlation, audience/recipient/destination/time/replay checks precede account policy and rotation. |
| `GET /saml/account/{tenant}/{owner}` | Exact current typed tenant/owner, current account generation/policy and current session recheck after the collaborator. |
| `POST /saml/logout/{local,redirect,post}` | Exact local Origin/session CSRF; end local session before provider preparation/admission/store work. Failure never restores it. |
| `GET /saml/logout-return/redirect`, `POST /saml/logout-return/post` | Separate saved single-use browser binding and connection, matching return binding and genuine signed correlated provider response. Never clear a newer independent session cookie. |
| `/saml/idp-logout/{connection}/{redirect,post}` | Trusted route selects receiver; accept only a genuine signed request, then compare the checked connection/entity, all five NameID components and session indexes before ending matching local sessions. |

Login and local logout POSTs require an exact singleton local `Origin`; `null`, absent, duplicate and foreign values refuse. Provider POST callback `Origin` is auxiliary: accept only the exact configured provider origin or singleton `null`. `null` does **not** identify or authenticate an IdP. The Fetch Standard permits a form's `Referrer-Policy: no-referrer` to suppress Origin, and core's transient SP form uses that policy. Saved server connection/browser pending state and the verified signed transaction are mandatory for either accepted value. A wrong signature or missing pending binding under `Origin: null` still denies. Redirect logout may omit Origin because it still requires its signed query and saved pending state. Serve local application form pages with `Referrer-Policy: strict-origin` so exact local Origin protection remains usable; do not loosen those local gates.

Primary explanation: [Fetch Standard, Origin header](https://fetch.spec.whatwg.org/#origin-header).

## Account/session handoff

Only `SamlAuthenticationResult.Succeeded` releases an authentication object. Login lookup uses **connection ID + exact IdP entity + complete stable subject key**. A stable key alone is not a tenant namespace. Missing/unmapped stable identity denies; email, display name, arbitrary attributes and transient NameID never substitute. The fixture's account mapping is deterministic test data, not a provisioning policy.

The recipe limits a stable key to 2048 ASCII characters and the genuine `SamlSessionReference` continuity representation to 4096. The actual immutable checked reference stays in trusted server memory. Measuring its serialized form is a size check, not parsing or accepting serialization as identity proof. The reference alone cannot authorize application data; each protected call performs current account/generation, exact tenant and object-owner checks. Authentication freshness and the original attempt/current session are rechecked after account collaborators and under final session publication. The host separately requires signed AuthnInstant to be at most five minutes old and no later than the current clock. Core also applies the saved forceAuthn option to the exact original pending request issue time: signed AuthnInstant earlier than that time minus the configured trusted skew refuses (zero skew here). The original request time is never reset at callback or after account work. These are checked signed-time policy assertions from the pinned IdP; they are not independent observation that the IdP actually performed reauthentication. Successful login atomically rotates the anonymous ID; its old session cannot access data. A concurrent local logout, expiry, cancellation or generation refusal cannot publish a replacement.

Sessions expire after at most 30minutes and earlier at checked `SessionNotOnOrAfter`. Assertion expiry is checked during login publication; it is not a promise of provider-wide revocation on every later local request. The current account callback owns revocation/authorization policy. Session cookies are `__Host-`, Secure, HttpOnly, Path=/, anonymous SameSite=None for POST callbacks and authenticated SameSite=Lax. Login/logout pending cookies are separately serialized SameSite=None. All fixture/device/browser transport and reverse-proxy trust assumptions remain explicit.

SP logout ends the local session before preparing the provider request. A valid single-use correlated Success is the IdP's authenticated report, not proof that every other application session ended. Non-success/partial provider outcomes must not be presented as complete propagation. Forged invalid responses leave a valid pending return available; there is no automatic retry. Indeterminate outcomes discard the local attempt and release no success. IdP-initiated logout matches value, Format, NameQualifier, SPNameQualifier and SPProvidedID plus the requested session indexes; a same display value under another connection/qualifier/index has no effect.

## Capacity, work and transport boundaries

The factory gives every configured connection its own immutable 128 replay slots through `InMemorySamlReplayCache.fromConnectionLimits`. A full connection cannot borrow another's reservation, unknown connections refuse, live fences are never evicted, and supported rollover retention can exceed this example's immediate five-minute acceptance policy. `fromLimit` is deliberately not substituted: its legacy quarter-total namespace policy is not a fixed per-IdP reservation.

App state caps 128 sessions,128 combined attempts,32 pending attempts per connection, and 262144 charged ASCII string/continuity bytes. Per-attempt retained session data is conservatively charged, including the old immutable continuity reference even after local logout. A full quota refuses without evicting live sessions/attempts. Each new allocation scans at most 16 attempts and 16 sessions with rotating scan progress. Observing an expired attempt/session removes its handle permanently, preventing later clock rollback revival. The charge is an exact application quota, not measurement of all JVM heap/DOM/container allocations.

Eight shared permits admit expensive callbacks, account work, explicit session admission and request preparation. The host checks interruption and an eight-second monotonic output budget around collaborators; collaborator implementations must honor the supplied remaining budget. It does not preempt arbitrary blocking Java code or promise to interrupt XML processing at a wall-clock threshold. Core additionally applies its bounded XML/decryption rules and one-second store/replay budget. No automatic network/store retry, read rescue, introspection or alternate credential path is added.

The host preserves raw header occurrences and refuses ambiguity: at most 32 names/occurrences, 4096 chars per value and 8192 aggregate header text. Local forms read 128+1bytes; SAML forms read 65536+1 using a counting wrapper around the actual Servlet reader. The extra byte causes refusal; a chunked stream is never silently truncated into a valid request. Raw query/form confusion, duplicated or aliased duplicated fields, invalid Base64 and duplicate cookies deny before pending consumption. A lone percent-encoded field name is standard form encoding, not a distinct duplicate; XML comments excluded by canonicalization can preserve the same logical signed subject.

Transient outbound forms have a restrictive CSP with fixed trusted form-action origin and no auto-submit script. Responses use no-store and redacted fixed errors. Do not log SAML documents, pending/browser secrets, account stable keys, session-reference forms or cookies. Edge/container configuration must also cap headers, upload time, framing, connection/thread admission and response delivery. Servlet containers can coalesce or reject physical header occurrences before the application observes them; qualify the exact reverse proxy/TLS/runtime path and reject lost ambiguity there. Never trust caller-supplied forwarding/scheme/Host headers without that fixed deployment policy.

## Evidence and remaining profile work

`verification/saml-sp-container` runs actual public APIs in pinned disposable Tomcat 9/11, deterministic JCA-signed XML and a separate real Chrome/private SAN TLS lane. It includes solicited Redirect and POST AuthnRequests; sealed pending outcomes; raw hostile carriers; account/current-session/cancellation races; bounded app admission; quota exhaustion; signed SP and IdP logout; and private planted defects.

The XML transforms are named exactly: wrong trusted key/issuer/audience/destination/InResponseTo/recipient, exact assertion expiry, future, one-second-before-original-request or over-five-minute-old signed AuthnInstant, unmapped identity, duplicate assertions/IDs, DOCTYPE external entity, malformed encrypted assertion, subject tampering, moving the signed assertion into an appended protocol Extensions element, appending an unsigned attacker assertion, replacing the enveloped transform URI with XSLT, and externalizing the assertion Reference URI. Several post-signing structural mutations also invalidate the response signature; those checks do not isolate a signature-valid wrapping primitive and are **not** the full XSW1–8 corpus or a Burp/SAML Raider/ZAP qualification pass. The canonical comment split is an accepted same-logical-subject control. The bounded malformed encryption case is not positive encrypted provider interoperability or the full encrypted mutation matrix.

The browser lane proves actual forms/cookies/rotation/login/logout over owned SAN-correct TLS with leaf-SPKI-scoped Chrome trust and no system trust change. It does not qualify hosted customer IdPs, every supported browser, reverse proxies, customer certificates/keys, durable restart/fleet recovery, full signed metadata freshness/rollover deployment, encrypted interoperability or formal S3 tool/profile gates. These remain explicit qualification work; this source/local packet does not close full M12 or shared-store C.
